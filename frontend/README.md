# Texas Hold'em Poker Frontend

Spring Boot 백엔드(REST + 순수 WebSocket)와 통신하는 텍사스 홀덤 웹 클라이언트. 서버가 게임 규칙을 전부 판단하고, 프론트는 서버가 내려주는 상태를 그대로 그리는 데만 집중한다 — 낙관적 업데이트나 클라이언트 측 규칙 검증은 없다.

로그인/게스트 인증 → 로비(방 목록/생성/검색/정렬) → 테이블, 3단계 화면으로 구성된 **멀티룸** 클라이언트다. 이 문서는 실제로 구현된 화면/기능만 기준으로 작성했다.

## 폴더 구조

```
src
├── 🌐 api            # REST 클라이언트 (httpClient, roomApi, authApi)
├── 🔌 ws             # WebSocket 훅 (연결/재연결/메시지 송수신, roomCode 기반)
├── 🗂️ state          # RoomContext — 전역 상태의 유일한 진실의 원천 (auth/lobby/table 화면 전환 포함)
├── 🃏 types          # 백엔드 DTO와 1:1 대응하는 타입
├── ♟️ game           # 순수 함수 (지금 가능한 액션 계산 등)
├── 🧮 lib            # 순수 유틸 (금액 포맷, 좌석 포지션, 족보 라벨/하이라이트)
└── 🎨 components
    ├── room          # 로그인/게스트 화면, 로비, 방 만들기/코드로 입장 모달, 게임 규칙 페이지
    └── table         # 포커 테이블 전체 (좌석/카드/칩/액션 UI, 방 정보 토글)
```

## 주요 기능

- **로그인/게스트 인증** — 아이디/비밀번호 로그인 또는 닉네임만으로 게스트 입장. 로그인 사용자는 가입 시 정한 닉네임을 테이블에서 그대로 쓰고(로그인 아이디는 노출 안 됨), 게스트는 입력한 닉네임 뒤에 `(Guest)`가 자동으로 붙는다
- **로비(방 목록/생성/검색/정렬)** — 방 목록을 한 줄씩 표시(이름/자물쇠 표시/대기중·게임중 배지/인원/블라인드·시작 칩), 제목 검색창, 제목·인원 정렬(인원 내림차순은 꽉 찬 방을 맨 아래로), 방 클릭 시 좌측 정보 패널(설정 확인 후 입장 — 바로 앉지 않고 관전자로 테이블을 먼저 보여줌), "방 만들기"(시작 칩/블라인드/비공개+비밀번호 설정, 만들면 바로 입장 — 좌석은 항상 6인 고정이라 인원 설정은 없음), "코드로 입장"(비공개방도 비밀번호 없이 바로 관전 시작)
- **게임방 내 방 정보 토글** — 좌측 상단 작은 버튼으로 방 코드/시작 칩/블라인드를 열람·공유
- **나가기** — 핸드 진행 중이 아니면 즉시, 진행 중이면 핸드가 끝난 뒤 퇴장. 마지막 1명이 나가면 방이 삭제된다는 확인 팝업 표시
- **GAME OVER 자동 리매치** — 생존자가 1명이 되면 15초 카운트다운 후 전원 칩 리필 + 레디 초기화, 다시 전원 레디하면 자동으로 재대결 시작
- **실시간 포커 테이블** — 좌석 배치, 내 좌석 항상 하단 고정, 원근감 있는 크기·간격(3D 변환 없이 CSS만으로), 딜러/블라인드 포지션 배지(BTN/SB/BB/UTG/HJ/CO, 인원 변화에 대응하는 구조)
- **WebSocket 실시간 동기화** — 연결 끊김 자동 재연결(1회) + 수동 재연결, 연결 상태 배지
- **액션 UI** — 체크/콜/폴드/올인 원클릭 버튼, 베팅/레이즈는 칩 프리셋으로 금액을 쌓아가는 빌더. "지금 가능한 액션"은 서버가 알려주지 않으므로 프론트가 직접 계산하되(`game/legalActions.ts`), 최종 검증은 항상 서버가 한다
- **쇼다운 결과 표시** — 족보 이름(로열플러시 별도 판정 포함), 승자 하이라이트, **실제로 승부를 결정한 카드만** 정확히 강조(무관한 킥커는 제외). 하이라이트는 족보 등급에 따라 7단계(하이카드~트리플 gold → 스트레이트 cyan → 플러시 indigo → 풀하우스 orange → 포카드 purple → 스트레이트 플러시 special → 로열 플러시 royal)로 색·광채·펄스 크기가 escalate된다
- **칩 시각화** — 보유 칩을 6단계 등급의 칩 더미 그래픽으로 표현, 핸드 종료 시 손익(+/-) 표시
- **카드/칩 애니메이션** — 딜링(카드 한 장씩 딜인 → 내 카드만 확인), 블라인드/베팅 칩이 팟으로 이동, 커뮤니티 카드 순차 공개(턴/리버는 더 느리게, 긴장감 연출), 쇼다운 시 상대 카드 순서 공개 → 팟이 승자에게 이동
- **홀카드 peek 토글** — 딜링 직후 자동 공개된 뒤로는 클릭할 때마다 뒷면/앞면을 토글(실제 홀덤처럼 확인 후 다시 덮어두기), 쇼다운 시엔 항상 앞면 고정
- **턴 타이머** — 액션 차례인 좌석에 60초 카운트다운 표시(좌석 배지 + 액션바), 10초 이하면 빨간색 강조
- **레디 시스템** — 수동 "핸드 시작" 버튼 대신 레디 토글, 파산하지 않은 전원이 레디하면 자동으로 다음 핸드 시작(첫 핸드는 1초, 이후엔 5초 카운트다운 표시)
- **헤즈업 머크 결정 UI** — 2인 쇼다운에서 상대가 자동 공개된 뒤, 내 카드 공개/머크를 8초 안에 선택(테이블 오른쪽 고정 패널, 액션바와 분리해 접근성 확보). 폴드로 이긴 핸드의 승자도 같은 패널에서 카드를 자원 공개할 수 있다
- **게임 규칙 페이지** — 족보 10단계를 카드 예시 + 하이라이트로 직접 보여주며 설명(실제 게임과 같은 하이라이트 색상 로직을 그대로 재사용)
- **고정 좌석제** — 방은 항상 6인용 고정 좌석. 빈 좌석을 클릭해서 입장하거나(로비에서 "입장"을 누르면 바로 앉지 않고 먼저 관전자로 테이블을 보여준 뒤, 빈 좌석 클릭으로 실제 입장) 이미 앉은 자리에서 다른 빈 좌석으로 옮길 수 있다(핸드 진행 중이 아닐 때만, 1초 연타 방지). 좌석마다 고정 색 점이 붙어 닉네임이 같아도 구분된다
- **방장 배지 + 강퇴** — 방을 만든 사람(또는 승계자)에게 🎖️ 배지. 방장은 레디 안 한 플레이어를 강퇴할 수 있다(핸드 진행 중이 아니고 레디 안 한 지 3초 이상 지났을 때만 — 남은 시간은 UI에 노출하지 않는다)
- **핸드 히스토리 / 블라인드 구조 / 족보 토글** — 좌측 상단 토글로 최근 30개 핸드 요약(클릭 시 상세), 판 수에 따른 블라인드·앤티 상승 스케줄 전체표, 게임 중 족보표를 각각 확인할 수 있다
- **사운드 효과** — 카드 딜링/공개, 블라인드/베팅/폴드/올인, 팟 이동, 내 차례, GAME OVER 승리에 상황별 효과음 + 스트레이트 이상 승리 시 영어 족보명 음성 안내. 헤더의 🔊 버튼으로 뮤트/볼륨 조절
- **로비 개편** — 방을 고르기 전에도 좌측 패널이 항상 같은 폭으로 고정되어(공지 패널 상시 노출), 방 목록에는 블라인드/시작 칩이 바로 보이고 "방 N개 · 플레이 중 M명" 통계도 표시된다. 로그인/로비 화면 상단에는 카드 그림 + "TEXAS HOLD'EM" 로고

## 상태 관리 원칙

- **서버 상태가 유일한 진실의 원천**이다. `RoomContext`가 REST 응답과 WebSocket `STATE` 메시지를 모두 같은 리듀서 액션(`ROOM_STATE_RECEIVED`)으로 처리하며, 클라이언트가 미리 결과를 그려두는 낙관적 업데이트는 하지 않는다.
- `playerId`와 `roomCode`는 `localStorage`에 함께 저장하되 **그대로 신뢰하지 않는다** — 새로고침 시 `GET /api/rooms/{roomCode}`로 서버에 실제 존재하는지(그 방에 그 좌석이 아직 있는지) 검증한 뒤에만 테이블 화면으로 복원하고, 없으면 지우고 로그인/게스트 화면으로 되돌린다(백엔드에 세션 개념이 없어 직접 관리해야 함).
- 화면은 `auth`(로그인/게스트) → `lobby`(방 목록) → `table`(게임) 3단계로 `RoomContext`가 관리한다. 로비에 있는 동안은 방 목록을 REST로만 조회하고, 실제로 방에 입장했을 때만(`roomCode`가 확정됐을 때만) WebSocket을 연다 — 로비 갱신을 위해 굳이 실시간 연결을 유지할 필요가 없기 때문이다.
- WebSocket 연결은 `roomCode`가 확정된 시점에만 열고, `onMessage` 콜백의 아이덴티티가 매 렌더 바뀌어도 재연결이 일어나지 않도록 최신 콜백을 ref로 감싸 effect 의존성을 `roomCode`/`playerId`로 고정했다.
- 게스트 닉네임은 `sessionStorage`에 저장한다(탭마다 독립적이라 같은 브라우저에서 여러 게스트를 테스트해도 서로 덮어쓰지 않음, 탭을 닫으면 사라짐). `playerId`/`roomCode`와 달리 **나가기로는 지우지 않고 로그아웃할 때만** 지운다 — 로비에서 다른 방에 새로 입장할 때도 같은 닉네임을 계속 써야 하기 때문이다.

| 단계 | 내용 |

| 1 | Vite + React + TypeScript + Tailwind 스캐폴딩 |
| 2 | 백엔드 CORS 설정 (dev origin만 허용) |
| 3 | REST 연동 — 참가/방 상태 조회/핸드 시작 |
| 4 | WebSocket 연동 — 실시간 상태 동기화, 재연결 |
| 5 | 포커 테이블 UI — 좌석/카드/팟/포지션 배지 |
| 6 | 액션 UI — 체크/콜/벳/레이즈/폴드/올인 |
| 6.5 | 폴리싱 — 쇼다운 결과, 칩 시각화, 규칙 페이지, 다수의 버그 수정 |
| 7 | 카드/칩 애니메이션 — 딜링/블라인드·베팅 칩 이동/커뮤니티 카드 순차 공개/쇼다운 리빌, `roomState`(진짜 최신)/`displayState`(연출 지연) 분리 아키텍처 |
| 8 | 게임플레이 완성도 — 턴 타이머+자동 폴드, 레디 시스템+자동 시작, GAME OVER 감지, 폴드승 카드 공개, 헤즈업 머크 결정, 홀카드 peek 토글, 족보 등급별 하이라이트 |
| 9 | 로그인/게스트 인증, 방 나가기, GAME OVER 자동 리매치(칩 리필) |
| 10 | 멀티룸 — 싱글룸 화면 구조를 로그인/게스트 → 로비 → 테이블 3단계로 전면 재구성. 방 목록/생성/검색/정렬, 좌측 정보 패널, 코드로 입장, 방 정보 토글, 로그아웃까지 실사용 피드백을 받아가며 짧은 주기로 반복 다듬음 |
| 11 | 게임 확장 — 핸드 히스토리, 블라인드 상승/앤티, 방장 배지/강퇴, 사운드 효과, 족보 모달까지 실사용 피드백을 받아가며 짧은 주기로 반복 추가 |
| 12 | 고정 좌석제 — 방을 항상 6인 고정 좌석으로 바꾸고, 로비 "입장"을 관전 → 빈 좌석 클릭으로 재구성. 과정에서 발견된 WebSocket 재연결 버그, 나가기 유예 시간 버그, 게스트 닉네임 유실 버그를 수정 |
| 13 | 로비 개편 — 좌측 패널 고정 레이아웃, 공지/통계/블라인드 노출, 로그인·로비 로고 추가 |

각 단계가 "세션 하나"에 대응하던 초반과 달리, 7단계 이후로는 애니메이션 뼈대가 갖춰진 뒤 짧은 주기로 기능 하나씩(설계→구현→테스트) 추가하는 방식으로 진행돼서 8단계 이후는 여러 기능을 한데 묶었다. 특히 10단계(멀티룸) 이후로는 기능 자체를 다 만든 뒤에도 실제로 써보며 나온 피드백(비공개방 노출 방식, 코드 입장 비밀번호 우회, 빈 방 자동 삭제, 정렬/검색 UX, 좌석 이동 시 화면 회전 방식 등)을 그때그때 반영하는 방식으로 계속 다듬었다 — 세부 내역은 위 "주요 기능"과 커밋 히스토리 참고.

## 기술적으로 흥미로웠던 부분

- **원근감을 3D 변환 없이 구현**: 테이블을 실제로 기울이는 CSS 3D(`perspective`+`rotateX`)도 시도해봤지만, 텍스트/카드가 같이 기울어져 가독성이 떨어지는 문제가 있었다. 대신 좌석 좌표 계산(`computeSeatPositions`)에서 나(하단)에 가까운 좌석은 넓게·크게, 먼 좌석은 좁게·작게 배치하는 "가짜 원근감"으로 정리했다 — 앉아서 보는 느낌은 유지하면서 텍스트는 항상 수평.
- **쇼다운 하이라이트의 "의미 있는 카드만" 판정**: 서버가 내려주는 `bestFive`를 그대로 다 하이라이트하면 원페어처럼 킥커가 섞인 족보에서 승부와 무관한 카드까지 강조되는 문제가 있었다. 족보별로 실제 조합을 구성하는 카드만(원페어=페어+최상위 킥커 1장, 트리플/포카드=조합 카드만, 스트레이트/플러시/풀하우스=5장 전부) 골라내는 로직(`getHighlightedCardsForShowdown`)으로 해결했다 — 이 로직은 동시에 족보 등급별 하이라이트 색상(`getHighlightColorForHandRank`)도 함께 반환해서, 카드 색·텍스트 스타일이 같은 곳에서 일관되게 결정된다.
- **REST/WebSocket 이원화가 만든 버그들**: "핸드 시작" REST 응답이 요청자를 모른 채(관전자 시점) 만들어져서 클릭한 사람 화면에서 순간적으로 본인 카드가 사라지던 문제, 폴드로 핸드가 조기 종료됐을 때 이미 끝난 베팅 라운드의 잔여 상태(`currentActorId`)가 응답에 남아 상대방 화면에 "아직 내 차례"처럼 보이던 문제 — 둘 다 REST와 WebSocket이 같은 게임 상태를 서로 다른 시점에 반영하면서 생긴 문제였고, 백엔드 응답을 개인화하거나 상태를 명시적으로 정리하는 방식으로 고쳤다.
- **`roomState`/`displayState` 분리와 그로 인한 버그들**: 애니메이션 큐 도입 후, 서버의 "진짜 최신 상태"(`roomState`)와 "화면에 지금 그려지는 상태"(`displayState`)가 몇백 ms~몇 초씩 어긋나는 구간이 생겼다. 이 구간에 액션 버튼이 옛 스트리트 기준으로 계속 활성화돼 있거나(스트리트 전환 애니메이션 중 `currentActorId`/`currentBet`을 얼려두지 않았던 버그), 액션과 무관한 상태 갱신(레디 토글)만으로 "방금 체크했다"는 라벨이 잘못 붙는 버그가 있었다 — 둘 다 "무엇을 근거로 액션이 실제로 일어났다고 판단할지"를 더 엄격하게(단순 `currentActorId` 비교가 아니라 `phase` 변화까지) 고쳐서 해결했다.
- **React StrictMode의 개발 모드 이중 실행이 만든 버그**: 홀카드 peek 토글에서 "이미 처리한 카드인지" 상태를 `ref`로 직접 추적했더니, StrictMode가 effect를 mount→cleanup→mount로 두 번 실행하면서 첫 실행이 ref를 먼저 갱신해버려 두 번째 실행이 "이미 처리됨"으로 오판, 타이머 예약 자체를 건너뛰어 기능이 아예 동작하지 않았다. `ref` 기반 수동 추적 대신 React가 권장하는 "prop이 바뀌면 `key`로 컴포넌트를 통째로 리마운트" 패턴으로 바꿔서 해결했다.
- **WebSocket 재연결 시 정상 연결 참조가 지워지던 버그**: 고정 좌석제 도입으로 "관전(`playerId=null`)하다가 좌석을 골라 입장"하는 흐름이 생기면서, `roomCode`는 그대로 두고 `playerId`만 바뀌는(소켓이 재연결되는) 이 앱 최초의 시나리오가 발생했다. 문제는 새 소켓이 이미 연결된 뒤에 옛 소켓의 `onclose`가 늦게 발동하면서, 조건 없이 `socketRef.current = null`을 실행해 방금 연결된 정상 소켓 참조까지 지워버린 것 — 그 뒤로는 폴드/체크/콜/올인처럼 서버 전송이 필요한 모든 액션이 조용히 실패했다(로컬 상태만 바꾸는 버튼은 정상 동작해서 원인 파악이 오래 걸렸다). `onclose`가 "지금 닫히는 소켓이 여전히 `socketRef`가 가리키는 그 소켓일 때만" 참조를 비우도록 한 줄 고쳐서 해결했다.
- **프론트 연출 시간과 백엔드 정책 시간을 일치시켜야 했던 버그**: 핸드 종료 후 결과 화면을 일정 시간(`RESULT_HOLD_MS`) 유지했다가 대기 화면으로 돌아가는 건 순전히 프론트 연출인데, "나가기"를 누르면 결과를 볼 시간을 주기 위해 3초 유예를 두는 건 백엔드 정책이었다. 둘이 서로의 기준 시각을 몰라서, 프론트가 이미 대기 화면으로 돌아간 뒤에도 "나가기"가 3초씩 더 늦게 처리되는 문제가 있었다 — 백엔드에 핸드 종료 시각을 기록해두고, 프론트의 `RESULT_HOLD_MS`와 반드시 같은 값을 쓰도록 주석으로 명시해 두 시간 기준을 동기화했다.

## 아직 구현하지 않은 것 (의도적으로 미룸)

- **닉네임 중복 방지**: 같은 방에 같은 닉네임으로 여러 명이 들어올 수 있다(좌석마다 고정 색 점으로 구분은 되지만, 이름 자체가 겹치는 건 막지 않는다).
- **3명 이상 쇼다운의 순서대로 머크**: 지금은 정확히 2명이 겨루는 헤즈업 쇼다운만 머크를 지원한다.
- **중간 입장 시 대기(스펙테이터 큐잉)**: 핸드 진행 중에 들어와도 곧바로 다음 핸드부터 참여한다 — "이번 핸드 끝날 때까지는 구경만" 하는 UI는 없다.
- **연결 끊김 자동 퇴장**: 탭을 닫아도(수동 "나가기"를 누르지 않으면) 서버 좌석은 남아있다.
- **로그인 토큰의 클라이언트 영속화**: 게스트 닉네임은 `sessionStorage`로 유지되지만, 로그인 토큰은 메모리에만 있어서 새로고침하면 재로그인이 필요하다.
- **최근 참여 방 바로가기 / 정렬 옵션 확장**: 로비에 "최근 플레이" 섹션이나 블라인드 크기순 정렬은 아직 없다.
